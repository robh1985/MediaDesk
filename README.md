# MediaDesk

One web portal for **Radarr, Sonarr, NZBGet, Jellyfin, Plex and PiKVM**, laid out like a desktop OS: draggable and resizable windows, a dock, a menu bar with live status, desktop widgets, notifications and a universal search launcher.

## Features

- **Users**: accounts with admin, standard and custom roles, the apps each person can use, profile pictures, invite links, password reset by email, passkeys (Face ID, fingerprint, Windows Hello), two-step sign-in with Google Authenticator, one shared eBook library with each person's own ♥ Mine list, personal game libraries, and links into the Family Organizer and Trip Planner. See [Users and sign-in](#users-and-sign-in).
- **Desktop shell**: windows that snap to screen edges (drag to the left/right edge, or the top to maximise), minimise to the dock, and remember their positions. Includes a light/dark theme, accent colours, built-in wallpapers or your own pictures (Fill, Fit, Stretch, Centre or Tile), and a mobile layout.
- **Dock, like macOS**: by default it shows Search & apps, the apps you have open, and Settings. Turn off *Show only open apps* in Settings → Dock & Desktop to keep your chosen apps in it instead; then you can drag apps to reorder them, drag one off to remove it, or use *Keep in Dock* on an open app. You can also choose its size, magnification and screen edge (left, bottom or right), hide it automatically, and show or hide open-app dots.
- **Arrange the desktop**: drag icons anywhere. Drop one app onto another to make a named group, like folders on Android; tap a group to open it, rename it, or drag apps back out. Drop a desktop icon onto the dock to add it. On phones, hold an icon and then drag it.
- **Launcher**: press `Ctrl+Space`, `Ctrl+K` or `/` to search apps, your Radarr/Sonarr libraries, Jellyfin and Plex in one place, run commands ("pause", "scan", "missing"), or type `add <title>` to add a movie or show.
- **Overview**: library counts, download speed, active streams, health warnings, what's airing this week, the download queue and recently added items.
- **Radarr / Sonarr**: browse and filter the library, see movie or series details (including seasons and episodes), search, monitor or unmonitor, refresh, delete, add new titles, manage the queue, and view the calendar, health and disk space.
- **NZBGet**: a live speed graph, pause and resume (everything or one download), a speed limit, move to top, delete, history (including retrying failed downloads), adding an NZB by URL or file upload, the message log, and server stats.
- **Jellyfin**: continue watching, next up, recently added, library browsing and search, item details (mark watched, favourite, refresh metadata), now playing (pause, stop or message a viewer), library scans, scheduled tasks, the activity log, and restart.
- **Notification badges**: when a download finishes or fails, a movie or episode is imported, or Radarr/Sonarr report a problem, a number appears on that app's icon instead of a pop-up. Opening the app clears it, and the bell lists everything. The server keeps watching even when no browser is open.
- **Plex**: manage your Plex Media Server: an overview (version, Plex Pass, library sizes, running activity), *Now Playing* with direct play / direct stream / transcode details, hardware transcoding, bandwidth and local or remote, plus *Stop stream* with a message to the viewer (Plex Pass). Also library scans, metadata refresh, empty trash, a library browser with item details (mark watched, refresh, delete), watch history, scheduled tasks you can run now, and maintenance (clean bundles, optimise the database, check for updates).
- **Plex Viewer**: watch Plex in the browser. A home screen with Continue watching, On deck and Recently added; library grids with sort, genre and unwatched filters; search; show pages with seasons and episodes. The player resumes where you left off, reports progress back to Plex (so it carries over to your other Plex apps), has quality, audio and subtitle choices, and plays the next episode automatically. Plex converts the video when the browser can't play it as is.
- **Family widget**: the desktop's *Family* widget shows what's left today and tomorrow in the Family Organizer, everyone's progress on today's chores, and tonight's dinner. Tap it to open the organizer. On short screens it shrinks to the next two events so the other widgets keep their room, and it can be turned off in the organizer's *Settings → General*.
- **Upcoming widget**: the desktop's *Upcoming* widget lists this week's TV episodes from Sonarr and the next month's movie releases from Radarr (in cinemas, digital and physical).
- **PiKVM**: the remote computer's live screen, with your keyboard and mouse (or touch, with an on-screen keyboard on phones); power on, shut down, force off and reset with the power LEDs; Ctrl+Alt+Del and other key combinations; paste text as typing (for long passwords or a BIOS); virtual media — upload, attach and detach ISO images as a CD-ROM or USB stick; GPIO switches; screenshots and full screen. MediaDesk signs in to the PiKVM, so its password never reaches the browser.
- **Log Viewer**: reads log files like Microsoft's CMTrace — Configuration Manager logs (both formats), Windows logs such as CBS.log, and any other text log. Errors are red and warnings yellow, with columns for component, date/time and thread, the whole entry underneath, and the elapsed time between selected lines. It follows a log as it grows, merges several logs into one timeline, and has Find (F3), Highlight, Filter (by text, component, thread or level) and an error-code lookup for Windows, HRESULT and ConfigMgr codes. Opens logs from the shared folders or your computer (drop files on it).
- **The Game Console**: an all-in-one game console for the games in a folder on your server: NES, Super NES, N64, Game Boy / Color / Advance, DS, Virtual Boy, Genesis / Mega Drive, Master System, Sega CD, 32X, Game Gear, Saturn, PlayStation, PSP, TurboGrafx-16, Atari 2600 / 5200 / 7800 / Lynx / Jaguar, Neo Geo Pocket, WonderSwan, ColecoVision, 3DO and arcade. Play with the keyboard or any USB or Bluetooth controller, remap every button per console and per player (up to four), and pick from ten looks: a 1980s–90s living-room entertainment centre, one inspired by Apple TV, and eight more inspired by easy console and TV menus. Drag game files onto it (or choose them in *Settings → Library*) and they're uploaded into the right console's folder. Saves, save states (with pictures) and *Continue where you left off* are kept on the server, so they follow you between devices. Each console has its own settings: emulator, BIOS, screen filter (including CRT looks), rewind, fast-forward and on-screen touch controls you can lay out yourself.
- **Settings for each app**: connection details, which events to count, and preferences such as the default quality profile and root folder for new titles, Sonarr's monitoring choice, the calendar range, the NZBGet category and priority, which Jellyfin user to browse as, and which home rows to show.
- **Music**: a Winamp-style player for your Jellyfin music library and the audio files in your shared folders. It has a green LCD display with a spectrum analyser, a 10-band equalizer with Winamp's presets, balance, shuffle/repeat, and a playlist editor. Its visualizer works like MilkDrop: GPU-rendered feedback warps react to bass, mids, treble and beats, with presets that blend into one another, and it can go full screen. Phones get lock-screen and headphone controls. Albums, songs and audio files can be sent to it from Jellyfin and Files.
- **Calculator**: basic, scientific (trigonometry in degrees, radians or gradians, powers, roots, logs, factorials, memory and history) and graphing (up to eight functions, with pan, zoom and tracing).
- **Notes**: a text and code editor like Notepad++, with tabs, syntax colours for about 40 languages and formats (code, config, logs, subtitles, CSV and more), line numbers, word wrap, find and replace with regular expressions, line tools (duplicate, move, sort, comment) and control over line endings and the BOM. It opens and saves files in your shared folders or on your device, and remembers open tabs, including unsaved ones.
- **Archive Expander**: a 7-Zip File Manager for the shared folders. Open an archive and browse it like a folder (archives inside archives too), view files inside it, and **Add**, **Extract**, **Test**, **Delete**, **Rename** and view **Properties**, as 7-Zip does. *Add to Archive* has 7-Zip's options: 7z, ZIP, TAR, WIM, GZip, BZip2 and XZ; compression level, method (LZMA2, LZMA, PPMd, BZip2, Deflate, Deflate64), dictionary and word size, solid blocks, CPU threads, split volumes, update modes (add/replace, update, freshen, synchronize), AES-256 encryption with encrypted file names, ZipCrypto, delete-after-compressing and extra `-m` parameters. *Extract* has full/no pathnames, the four overwrite modes, *eliminate duplication of root folder* and passwords. It also calculates checksums (CRC32/64, XXH64, SHA-1/256/384/512, SHA3-256, MD5, BLAKE2sp) and runs 7-Zip's benchmark. It opens everything 7-Zip opens (7z, ZIP, RAR/RAR5, TAR, GZ, BZ2, XZ, ISO, UDF, CAB, CHM, MSI, DMG, HFS, APFS, VHD/VHDX, VMDK, VDI, QCOW, WIM, NSIS, RPM, DEB, CPIO, ARJ, LZH, squashfs, split `.001` files, …; *Tools → Supported formats* lists them). Files gets *Open in Archive Expander*, *Extract Here*, *Extract to “name/”* and *Add to archive…*. Needs 7-Zip on the server; see [Helper programs](#preview-helpers).
- **Convert**: a unit converter in the style of Josh Madison's Convert, with 26 categories and 474 units: acceleration, amount of substance, angle, area, computer storage and data rate, concentration (molar and mass), density, distance, energy, flow, force, frequency, fuel economy, light (illuminance and luminance), mass, power, pressure, speed, temperature (Celsius, Fahrenheit, Kelvin, Rankine, Réaumur, Rømer, Newton, Delisle), time, torque, volume and dry volume. The answer updates as you type (sums like `5*12+11` work), with decimal places, scientific notation and digit grouping, a swap button, a table of the value in every unit, and your own units and categories (saved in the browser). Factors come from the exact definitions (international inch and pound, US and imperial gallon, standard gravity, IT BTU and calorie).
- **Paint**: a classic Windows 98 Paint, after jspaint. It has all 16 tools (free-form and rectangle select, eraser and colour eraser, fill, pick colour, magnifier, pencil, brush, airbrush, text, line, curve, rectangle, polygon, ellipse, rounded rectangle) with their size and fill options, and the 28-colour palette with *Edit Colors*. Selections can be moved, copied (Ctrl-drag) and smeared (Shift-drag), opaque or transparent. The Image menu flips, rotates, stretches, skews and inverts, and sets the size in *Attributes*; you can also drag the canvas edges. There are zoom levels with a grid, undo and redo, the clipboard, *Copy To*/*Paste From* and *Set As Wallpaper* (tiled or centred). It opens pictures from the shared folders and saves PNG, JPEG, BMP or WebP.
- **Paint Pro**: a layered image editor modelled on Pinta. It has 22 tools: the four selection tools with replace, union, exclude, xor and intersect modes; magic wand; move selected/selection; zoom; pan; paintbrush; pencil; eraser; paint bucket; gradient (linear, reflected, diamond, radial, conical; colour or transparency); colour picker; text; line/curve; rectangle; rounded rectangle; ellipse; freeform shape; clone stamp; and recolour. Shapes stay editable with handles until you finish them. Layers have opacity, blend modes, hiding, reorder, duplicate and merge down, and there is a history panel you can click back through. There are 9 adjustments (auto level, black and white, brightness/contrast, curves, hue/saturation, invert, levels, posterize, sepia) and 32 effects in Artistic, Blurs, Distort, Noise, Photo, Render and Stylize, all with a live preview limited to the selection. It also has tabs for several images, resize, canvas size, crop, flip and rotate, and screenshots. Files are saved as OpenRaster (`.ora`, which keeps layers), PNG, JPEG, WebP or BMP. Files gets *Edit in Paint* and *Edit in Paint Pro*.
- **Family Organizer**: a family hub like a Skylight Calendar, shared by every device in the house (it's kept on the MediaDesk server). Each section in its left-hand menu has its own colour. Sections with parts of their own open a second menu of them right beside it, in the same style: Calendar (Day, Week, Month, Schedule), Chores (Chores, Routines), Meals (Meal plan, Recipe box), Lists (each list, with how many things are left and who it's for, plus *New list*) and Settings (My account, Accounts, Calendars, General, Photo frame & sleep, Chores/Routines). On a phone they're a grid across the top.
  - **Calendar**: month, week, day (a column for each person) and schedule views, colour-coded by person, with the weather on each day and countdowns to big days. Events can repeat (daily, weekly on chosen days, monthly by date or "second Tuesday", yearly), have reminders, a place and notes. Repeating events can be changed or deleted one at a time, from one onwards, or all together. Drag events to move them or drag their bottom edge to resize them. *Quick add* turns what you type ("Soccer every Tuesday 4:30-6pm for Leo") into events, several at once, and reads `.ics` files.
  - **Imported .ics files**: each import (from *Settings → Calendars → Import*, or a file dropped in *Quick add*) is listed by file name, with how many events it added and *Remove events* to take them all out again. Importing the same file again updates its events rather than doubling them. *Remove events from a file…* takes out the events matching any .ics file (same title and start), including imports made before they were listed.
  - **Family calendars**: alongside the main family calendar, parents can create calendars of their own in *Settings → Calendars* (Soccer, School, Work …). They have the same options as a connected calendar: a name, whose calendar it is (its events then take that person's colour and show in their column), a colour for when it's everyone's, and whether it's shown. A new calendar can start with the events from an .ics file, named after the file, and more files can be imported into it later. When adding an event, choose which calendar it goes on, and its events show in that calendar's colour. A calendar can be turned off for everyone, or shown and hidden on one device with the *Calendars* button. Deleting one moves its events to the main family calendar, or deletes them too.
  - **Connected calendars**: Google, Outlook, iCloud, Yahoo, Cozi, school and team calendars, added by their iCal address and read every 10 minutes. The family's own events have a private subscription address for phones.
  - **Chores and routines**: a chore chart with a column per person, chores that repeat on chosen days, "up for grabs" chores, morning, afternoon and evening routines, a week-at-a-glance chart and a celebration when a chore is ticked off.
  - **Approvals**: signed in to a parent account, the left menu has *Approvals*, with a count of everything waiting for a parent: chores family members made for themselves and extra chores they did. Approve each (changing its stars first if you like), decline it, or *Approve all*.
  - **Extra chores**: a collapsible menu on the right of the Chores tab lists one-off jobs (Wash the car, Rake leaves, Help make dinner …). Tapping one adds it as a *just once* chore for whoever is signed in, already ticked off. Inside MediaDesk it asks who did it. Its stars count once a parent approves it in *Approvals*. Parents choose what's on the menu in *Settings → Chores/Routines*.
  - **Quick picks**: adding a chore starts with a *Quick pick* drop-down of ready-made chores (on the Chores tab) or routine steps (on the Routines tab). Choosing one fills in the name, emoji, stars, how often and part of the day, and everything can still be changed before saving. Parents manage the list in *Settings → Chores/Routines*: they can add, change, reorder or remove picks, or restore the suggestions it starts with. Family members can use the picks but not change them.
  - **Helping out and making your own chores**: on the organizer's own page, ticking off someone else's chore gives you the stars, and the chore shows *Done by* you. (A signed-in parent is asked who did it.) A family member can make a chore for themselves. It's marked *Waiting for a parent to approve*, and can be ticked off meanwhile, but its stars only count once a parent approves it, in *Approvals* (or *Chores → Approve*). The parent can change its stars when approving (times already ticked off then count) or decline it. The server enforces this: a family member's ticks always credit themselves with the chore's own stars, and they can't change other people's chores, approve their own, or give themselves stars.
  - **Rewards**: stars earned from chores are spent on rewards. Parents can give or take stars, and there's a star history.
  - **Meals**: a weekly meal plan (breakfast, lunch, dinner, snack), a recipe box, meal ideas and *Plan dinners for me* from the recipe box, and ingredients sent to the grocery list.
  - **Recipe box**: modelled on Mealie. Recipes have a photo, a description, prep, cook and total times, servings or what they make, ingredients and steps (both can have sections, like *For the sauce*), notes, nutrition, categories, tags and tools. Search covers names, ingredients and tags. You can filter by favourites, category, tag, tool or where a recipe came from, and sort by name, newest, rating, quickest or recently made. Each recipe has a star rating, a favourite heart and a *Made it today* count. The servings scaler changes the amounts in the ingredients (fractions included), and those scaled amounts go to the grocery list. *Print view* opens a clean page of the recipe to look over, with its own Print button, and *Print* prints it straight away. *Cook mode* is full screen and shows one large step at a time, with the ingredients alongside. You move between steps by swiping or with the arrow keys. Times in a step ("simmer for 20 minutes") become timers that chime when done, and the screen stays on while you cook. *From a website* imports a recipe from most recipe sites, with its photo, for you to check before saving. Your own photos can be added to any recipe.
  - **Cookbooks**: group recipes into cookbooks (Weeknight dinners, Grandma's favourites, Holiday baking …), each with an emoji, a colour and a description. They sit on a shelf at the top of the recipe box, and opening one shows only its recipes, with search and filters still working. Add recipes from the cookbook (*Add recipes*), or from a recipe's *📚 Cookbooks* button, which also lists the cookbooks it's in. A cookbook can also fill itself: pick categories, tags or tools, and every recipe with one of them goes in, including recipes added or imported from Mealie later. Taking one of those out keeps it out. *📖 Open book* shows a cookbook as a book you read on screen. Wide screens show an open book, two pages side by side with a spine, and phones show one page at a time. It has a cover, a contents page (tap a recipe to jump to its page), then each recipe laid out over as many pages as it needs, starting on a left-hand page, with running headers and page numbers. Turn pages with the arrows, the arrow keys, a swipe or a tap near a page's edge, and the page turns over in 3D. *Contents* jumps back, and *Open in the recipe box* at the end of a recipe opens it to cook from. *Print view* on a cookbook gives a printable book: a cover, a contents page, then each recipe on its own page. Deleting a cookbook keeps its recipes.
  - **Mealie**: if you run your own [Mealie](https://mealie.io), a parent connects it in *Settings → General → Mealie recipes* with its address and an API token (in Mealie: your profile → *API Tokens*). Every Mealie recipe is imported with its photo, sections, times, categories, tags, tools, notes, nutrition and rating. The import runs again automatically every 15 minutes, hourly, every 6 hours or daily (or only when asked). Each run fetches only new and changed recipes, and recipes deleted in Mealie leave the recipe box. Imported recipes link back to Mealie with *Open in Mealie*. Changes to them belong in Mealie, because the next import replaces edits made here, but ratings, favourites and *Made it* counts given here are kept. Parents can also *Import now*, from Settings or above the recipe box. Disconnecting either keeps the imported recipes as the family's own or removes them. The token stays on the MediaDesk server and is never sent to browsers.
  - **Lists**: grocery lists sorted into aisles as you add to them (see *Groceries* below), to-do lists with a person and a due date, and any other list. To-do lists (and their items) can be assigned to family members. Parents assign them to anyone; signed in as a family member, you can add or take off only yourself. Picking people at the top shows their lists plus everyone's. The × on any item removes it from the list, with *Undo* in case it was a mistake.
  - **Groceries**: a database of about 500 everyday foods, each in its aisle, plus the family's own foods. Typing on a grocery list suggests foods as you type ("straw" → Strawberries), keeping any amount you typed ("2 lb ground beef"). Each item can have a **quantity**, an optional **brand** and an optional **kind or flavor** (ice cream, chips, cereal…), in the *Qty*, *Brand* and *Kind / flavor* boxes beside it (or the quantity typed with the item: "1 dozen eggs", "2 gallons milk"); they show on the item, can be changed by tapping it, and brands you've used before are suggested, as are the flavors you've had of that food. An item can have **several kinds or flavors**: type one and press Enter (or a comma) and it becomes a chip, then the next; × takes one off, and past flavors of that food are offered to tap. Adding more flavors of something already on the list puts them on that item. At the store, tap a flavor when it's in the cart (it's crossed off); when they all are, the item is ticked. The same food in two brands is two items. *Foods* opens the whole database by aisle, where you can search and tap foods onto the list (tap again to take one off). A food that isn't in the database yet is added to it, either straight away with the aisle it seems to belong in, or with *Add a food*, where you choose its aisle. Items are sorted into aisles automatically. If one is in the wrong aisle, tap its aisle button (or open the item) and pick the right one, or make a *New aisle*. That food then goes to the aisle you picked from then on. *Aisles* puts the aisles in the order you walk through your store. Aisles can be added, renamed, moved and removed, and the standard aisles can be restored. Foods in the database can be renamed, moved to another aisle or removed.
  - **Photos**: a photo frame slideshow from uploaded photos or a shared folder, showing the time, weather and what's next. It can start by itself when nobody's using the organizer.
  - **Light and dark mode**: the ☀️/🌙 button at the top switches the screen you're on between light and dark (on a phone, it's in the account menu). *Settings → General → Appearance* has the rest. Each screen can follow the family's setting or choose for itself, and that choice is kept on the device, so the kitchen tablet can be dark while phones stay light. Parents set the family default: *Automatic*, *Light*, *Dark*, or *Dark at night* between hours you choose. *Automatic* follows MediaDesk's theme inside MediaDesk, and the device's own light/dark setting on the organizer's own page (`/family`).
  - **Sleep mode** at night, and a **parent PIN** for settings, chores, rewards and stars.
  - **On its own:** the organizer also works by itself in any web browser at `http://<your MediaDesk>/family`, and can be added to a phone's home screen. There it has its own accounts. A parent makes an invite code in *Settings → Accounts* (for a parent or a family member, optionally tied to their profile, and working for 1 to 30 days). The person opens the invite link, or enters the code, and creates their account with their first name, last name, email, a username and a password. Parents manage accounts in *Settings → Accounts*, along with the family's profiles and the parent PIN: they can change names, emails and roles, link a profile, set a new password, turn an account off or remove it. Everyone can change their own details and password in *Settings → My account*, which comes first in Settings. If their account is linked to a family profile, *My profile* there lets them choose their picture (an emoji or a photo of themselves) and their colour. Everyone has their own colour: colours other people already have are marked with their initial and can't be picked, and the server refuses them too. Parents get the same picture and colour choices when editing any profile. Parents can change settings, profiles and connected calendars, and family members can use everything else. The first parent account is made by someone signed in to MediaDesk: either open `/family` in the same browser, or make a parent invite in the organizer inside MediaDesk. Signed in to a parent account, the parent PIN isn't asked for. Inside MediaDesk it still is, because MediaDesk is often on a shared screen. If MediaDesk has no portal password, its own pages (and so the family's data) are open to anyone who can reach it, so set one when `/family` is reachable from outside your home. In demo mode, sign in as `maria` (a parent) or `emma`, with the password `family-demo`.
  - Weather comes from Open-Meteo, which needs no account. Two-way sync with Google or Outlook needs their sign-in, which MediaDesk doesn't have, so connected calendars are read-only. Events added in the organizer reach phones through the subscription address instead.
- **eBook Reader**: your books on a bookshelf (EPUB, PDF, Kindle MOBI / AZW / AZW3, FictionBook FB2, plain text, and comic books in CBZ, CBR, CB7 or CBT), read as a flipbook like [AnyFlip](https://anyflip.com). The book lies open on the screen, two pages side by side (one at a time on a phone or narrow window), and pages turn like paper. Drag a page's corner and it curls over, following the pointer with the page behind showing through and shadows along the fold. Let go past the middle and it turns, otherwise it falls back. Hovering near a corner lifts it a little, and a click, tap, swipe or the arrow keys turn pages too. The covers are stiff and swing over on the spine, and a closed book sits in the middle of the screen. There's a page slider, thumbnails of every page, the book's contents, search (with matches highlighted), bookmarks, zoom (double-click, Ctrl + scroll or the buttons, then drag to look around), auto-flip, a page-turn sound, full screen and a dark, wood or light background. EPUB books flow into pages that fit the screen, with a choice of text size, typeface, line spacing and white, sepia or night pages. Their links and footnotes work. The library has *Continue reading*, search, sorting and filters, with each book's cover from inside it (a PDF's first page is drawn once and kept). Where you're up to and your bookmarks are kept on the server, so a book opens at the same page on any device. Choose the books folder in *Settings → eBook Reader* (or set `EBOOKS_DIR`). Books in shared folders open from Files (straight away, or any book with *Read in eBook Reader*). *Open a book* also takes one from the device you're on, and offers to add it to your library: it's uploaded into the books folder (or one of its folders) and your place in it carries over. *Add books to the library…*, or dropping books onto the library, adds several at once, with comics going into a `Comics` folder if there is one. The books folder has to be writable for this. EPUB, PDF, MOBI / AZW, FB2, text and CBZ open in the browser as they are. CBR (RAR), CB7 and CBT comics are repacked by the server's 7-Zip (see [Preview helpers](#preview-helpers)), and AZW3, Word (DOCX), RTF, ODT and LIT books are converted to EPUB by [Calibre](https://calibre-ebook.com)'s `ebook-convert` when it's installed on the server (it's found on the PATH or where Calibre installs, or set `EBOOK_CONVERT_PATH`; see [Preview helpers](#preview-helpers)). Each conversion happens once and is kept. Without Calibre, an AZW3 is read from the MOBI copy most of them include. Books with DRM can't be opened. **Kindle:** the 📲 Kindle button backs up the books on the device you're using (a Kindle Fire, say: books you've downloaded or copied onto it, from Books, Documents or Download) into a folder of the library, skipping any already there; books bought from Amazon stay inside the Kindle app and are protected, so they can't be backed up this way. It also sends library books to the Kindle app, two ways: *Download for the Kindle app* saves a Kindle copy on the device (MOBI, AZW3, PDF and text as they are; other books made into AZW3 by Calibre), with the steps to find it in the Kindle app's library; *Send to Kindle* emails it to your @kindle.com address, so Amazon adds it to your Kindle library on every device and keeps your place in step (EPUB, PDF, Word, RTF and text as they are; Kindle books become EPUB and comics PDF, through Calibre; up to 50 MB). Send to Kindle is set up in *Settings → eBook Reader* with your Kindle address and your own email account's server (SMTP: Gmail, Outlook and the like; the password stays on the server). Add the sending address to the Approved Personal Document E-mail List at Amazon. Both are in Files too: a book file's menu has *Send to Kindle…*, and *Back up books* (in the toolbar and the folder's menu) copies a device's books into the folder you're in, skipping ones already there (in the books folder, they join the library).
- **Trip Planner**: plan trips together, with the features of [TREK](https://github.com/liketrek/TREK). A trip has its own currency and distance unit (miles by default, or kilometers), starts from somewhere (home, say) and goes to one destination or several (towns, regions or countries, suggested as you type), each with the days you're there and how you get there: a road trip, flight, train, bus, ferry, boat or something else, each with its own details (airports and flight number, stations, ports, rental car, avoiding tolls…). The plan's menu starts with where you set off; before each destination comes the journey there. Driving routes, once worked out, are kept with the trip (and shown on its share page and printout) until you clear them or the journey's start or end changes. A flight shows the airport you leave from (the nearest big one unless you choose) with driving directions to it, and a road trip has driving directions to the next destination drawn on the map, with a search for hotels, camping, sights, food, viewpoints, fuel, EV charging and rest areas along the route. Each destination folds open to its own places to visit and days, and the map opens on the first one. Each trip is planned day by day beside a map: search for places (OpenStreetMap), click the map to add one, or explore what's nearby by kind (sights, museums, food, cafés, viewpoints, nature…). Drag places and notes between days, see each day's route with its distance and time on foot, by bike or by car, put a day in the shortest order (keeping chosen stops in place), and open it in Google Maps. Days show the weather (the forecast, or last year's as a guide) and where you're staying. Places get a description and picture from Wikipedia, notes, a rating, files and links to 7 navigation apps. Import places from GPX, KML / KMZ, GeoJSON, Google Takeout or a Google Maps link, and export GPX or a calendar. *Bookings* keep flights (with airports looked up by code or city and several legs), trains, stays (hotels, short-term rentals such as Airbnb or Vrbo with the site they were booked through, apartments, camping and hostels, each with check-in and check-out times, shown on the plan's days), cars, tables and tickets, with booking codes, files and who's going; their price can go straight into the costs. *Costs* splits what you spend equally, by shares or by amounts, in any currency (at the day's exchange rate), shows who owes whom and the fewest payments to settle up, tracks a budget and exports a spreadsheet. *Packing* lists have categories, quantities, who packs what, bags with weights and limits, and templates; *To-dos* have due dates, priorities and assignees. *Files* holds tickets and photos (with a bin), and *Notes* has shared notes, links and polls. Share a trip with a read-only link (choose what it shows) or as a calendar feed, print it or save it as a PDF, copy and archive trips, and undo changes. The *Atlas* colours the countries you've been to and your bucket list. Everyone signed in to MediaDesk sees the same trips, and changes show up for the others within a few seconds. See [The Trip Planner](#the-trip-planner).
- **Preview**: opens files from Files. You can flick through pictures in a folder, zoom and rotate them, and see TIFF, HEIC and PSD files. Video and audio play in any format, converted on the server while they play when the browser can't handle them, with audio-track choice. PDFs have selectable text. Word, Excel and PowerPoint files open too. See [Preview helpers](#preview-helpers).
- **Screensaver**: eleven classics: Flying Toasters (in isometric 3D), 3D Maze (Windows 98), 3D Pipes, Starfield, Mystify, 3D Text, Bubbles, Ribbons, Flurry, Hello (macOS) and Matrix (the falling green code from The Matrix), or a random one each time. Turn it on and pick the delay in Settings → Screensaver. With *Require password to return* on, it locks MediaDesk in every tab until the portal password is entered again; music from Jellyfin keeps playing. The MediaDesk menu can also start the screensaver or lock the screen right away.
- **Live scores (NFL, NBA, NHL, MLB)**: while games are on, the menu bar shows each one in turn: both teams' logos and scores, the quarter, period or inning and the clock, a small league tag when more than one league is on, a dot by the team with the ball (NFL) and red in the red zone, and for baseball the runners on base and the outs. A game that just changed score flashes and shows next, then the turn carries on. Hover to hold a game; click for the day's games (the NFL's week) with a tab per league: live (down and distance, the count, batter and pitcher, the last play), finals, and start times with the TV channel. In *Settings → General → Menu bar*, turn each league on or off, and show only your teams in each (`KC, BUF`). Scores come from ESPN's public scoreboards, asked for by the MediaDesk server at most every 15 seconds per league during its games (every 5 minutes otherwise) however many browsers are open; logos are downloaded once and kept next to `config.json` (a badge in the team's colours if they can't be).
- **Maps**: a world map with twelve base maps (streets, terrain, satellite, hybrid, topographic, USGS topo, lidar relief, light, dark, cycling, humanitarian and Earth at night) and layers on top, each with its own opacity: worldwide hillshade, **lidar** hillshade, multidirectional hillshade and slope for the United States (the USGS 3D Elevation Program's bare-earth lidar, showing the ground under the trees), place labels, roads, hiking and cycle routes, railways, sea marks and live weather radar. Search for places and addresses (or paste coordinates), click anywhere for the address, coordinates (decimal and degrees–minutes–seconds) and the height of the ground (from 3DEP lidar in the US, and Copernicus 90 m terrain elsewhere), show where you are, and measure distances and areas in miles or kilometres. The **route planner** (the ◇ button, a place's *Directions to here*, or right-clicking the map) gives driving, cycling or walking directions from one place to another with stops on the way (typed, picked on the map, or *Your location*), avoiding tolls, motorways or ferries if you like, with up to three alternative routes, the time and distance of each, and turn-by-turn steps (click one to see where it is). Drag a marker to change the route, swap start and destination, print the directions or open them in Google Maps. Routes come from OpenStreetMap data, worked out by the FOSSGIS OSRM servers (`routing.openstreetmap.de`) through the MediaDesk server. The map remembers where you were and the layers you chose. Map pictures come straight from their free providers (OpenStreetMap, OpenTopoMap, Esri, USGS, CARTO, CyclOSM, NASA, Waymarked Trails, OpenRailwayMap, OpenSeaMap, RainViewer), so the browser needs internet access.
- **Files**: a file manager for folders you choose on the MediaDesk server. You can browse, upload (drag and drop, any size), download, create folders, rename, cut/copy/paste, drag files between folders and delete. Pictures, video, PDFs and Office files open in Preview, `.log` files in Log Viewer, other text files in Notes, and any picture can become the wallpaper. Shared folders can have an alias (a friendlier name, shown with the full path under it) and colour tags you create, so you can group them and filter the sidebar by tag. Open several folders as **tabs** (each with its own back and forward), and connect **network shares** (Windows / NAS shares, NFS, SFTP and WebDAV) as shared folders. See [Files](#files).
- **Web UI windows**: open any service's own interface inside a window for anything MediaDesk doesn't cover.

Your API keys stay on the MediaDesk server. The browser only talks to MediaDesk, which adds the credentials when it forwards each request. This also avoids CORS problems.

## Quick start

### Try the demo first (no servers needed)

```bash
npm run demo        # or: node server.js --mock
# open http://localhost:8080
```

### Docker Compose

```bash
docker compose up -d --build
# open http://<your-server>:8080, then open Settings and connect each app
```

Edit `PORTAL_PASSWORD` in `docker-compose.yml` first: it becomes the password of the first account, **admin** (see [Users and sign-in](#users-and-sign-in)). Settings you save in the UI are stored in `./config/config.json`.

If your media apps run in the same Compose project or Docker network, use their container names as URLs (for example `http://radarr:7878`).

### Plain Node.js (18+)

```bash
PORTAL_PASSWORD=change-me node server.js
```

There are no dependencies and nothing to `npm install`.

### Windows

1. Install **Node.js LTS** from <https://nodejs.org> (the default options are fine).
2. Download MediaDesk: either `git clone https://github.com/robh1985/MediaDesk.git`, or on GitHub click *Code → Download ZIP* and extract it. A permanent spot like `C:\MediaDesk` works best.
3. Pick how you want to run it:

| | How | Good for |
| --- | --- | --- |
| **Try it** | Double-click `start-windows.cmd`. To use sample data instead, run `start-windows.cmd --mock` from a command prompt. | Testing. It stops when you close the window. |
| **Run all the time** | Double-click `install-windows.cmd` and approve the admin prompt. | Everyday use. It starts with Windows (even before anyone logs in) and restarts if it crashes. |

`install-windows.cmd` does the following:
- asks for a portal password
- registers a startup task called **MediaDesk**
- opens the port in Windows Firewall for Private networks
- starts the portal and opens it in your browser
- prints the address other devices on your network can use

To use a different port, run it from a command prompt as `install-windows.cmd -Port 8081`. Run it again at any time to change the password or port.

Notes for Windows:
- **Service URLs:** if Radarr, Sonarr, NZBGet or Jellyfin run on the same PC, use `http://localhost:7878` and so on on each app's page in *Settings*.
- **Other devices can't connect:** check that the network is set to *Private* in Windows Settings → Network. The firewall rule doesn't apply to *Public* networks.
- **Update:** double-click `update-windows.cmd`. It downloads the latest version from the `main` branch (switching to `main` if you're on another branch) and restarts MediaDesk. If you installed from a ZIP, extract the new ZIP over the old folder and double-click `restart-windows.cmd`. Your settings are kept either way. Settings → About shows which version is running.
- **Restart:** double-click `restart-windows.cmd`. This stops any leftover copy of MediaDesk before starting it again; ending the task in Task Scheduler doesn't always do that.
- **Logs:** the background version writes to `logs\mediadesk.log`, including the version it started with and any startup errors.
- **Remove:** double-click `uninstall-windows.cmd`. Your settings are kept.
- **Docker Desktop** also works with `docker compose up -d --build`. In that case, services running on the Windows host are reached at `http://host.docker.internal:7878`, not `localhost`.

## Configuration

You can configure MediaDesk in three ways. Environment variables override the config file.

1. **Settings app** (easiest): open *Settings*, pick an app in the sidebar, fill in its connection fields and click *Save & reconnect*. *Settings → General* tests every connection at once.
2. **`config/config.json`**: see `config/config.example.json`.
3. **Environment variables**:

| Variable | Purpose |
| --- | --- |
| `PORTAL_PASSWORD` | The first time MediaDesk starts without accounts, this becomes the password of an **admin** account (sign-in turns on). After that, accounts are managed in *Settings → Users*. **Set this** (or make an account in Settings → Users) if anyone else can reach the portal. |
| `RADARR_URL`, `RADARR_API_KEY` | Radarr → *Settings → General → API Key* |
| `SONARR_URL`, `SONARR_API_KEY` | Sonarr → *Settings → General → API Key* |
| `NZBGET_URL`, `NZBGET_USERNAME`, `NZBGET_PASSWORD` | NZBGet → *Settings → Security* (`ControlUsername` / `ControlPassword`) |
| `JELLYFIN_URL`, `JELLYFIN_API_KEY` | Jellyfin → *Dashboard → API Keys → +* |
| `PLEX_URL`, `PLEX_TOKEN` | Easier: *Settings → Plex → Sign in with Plex*. Otherwise the server address (`http://<ip>:32400`) and an `X-Plex-Token` |
| `FILE_ROOTS` | Optional. Folders the Files app may manage (also settable in *Settings → Files*) |
| `PIKVM_URL`, `PIKVM_USERNAME`, `PIKVM_PASSWORD` | PiKVM's address (for example `https://192.168.1.50`) and its web login (user `admin` by default) |
| `GAMES_DIR` | Optional. The Game Console's games folder (also settable in *Settings → The Game Console*) |
| `PUBLIC_URL` | Optional. MediaDesk's address as people reach it (e.g. `https://media.example.com`), for the links in invite and password reset emails. Without it, the address an admin last opened MediaDesk at is used |
| `EBOOKS_DIR` | Optional. The eBook Reader's books folder (also settable in *Settings → eBook Reader*) |
| `EBOOK_CONVERT_PATH` | Optional. Calibre's `ebook-convert`, for AZW3, Word, RTF, ODT and LIT books in the eBook Reader (found automatically when Calibre is installed) |
| `OVERPASS_URLS` | Optional. The Trip Planner's Overpass servers (for exploring nearby and along a route), comma-separated, tried in turn when one is busy. Defaults to the public ones |
| `PHOTON_URL` | Optional. A Photon server for the Trip Planner's destination suggestions and nearby / along-the-route searches (default `https://photon.komoot.io`) |
| `NOMINATIM_URL` | Optional. A Nominatim server for the Trip Planner's place search (default `https://nominatim.openstreetmap.org`) |
| `JELLYFIN_USER_ID` | Optional. Which user's view to browse (defaults to the first admin) |
| `*_PUBLIC_URL` | Optional. The browser-facing URL used for "Open in…" links and Web UI windows, if it differs from the server-side URL |
| `PORT`, `HOST`, `CONFIG_PATH` | Server settings (defaults: `8080`, `0.0.0.0`, `./config/config.json`). The port can also be set as `"port"` in the config file. |

**Server URL compared with public URL:** the *server URL* is how the MediaDesk server reaches a service (for example `http://radarr:7878` inside Docker). The *public URL* is what your browser uses (for example `https://radarr.example.com`) and only matters for links and embedded web UIs.

## Files

The Files app only works with folders you've shared in **Settings → Files**, which takes one full path per line, such as `D:\Media` or `/mnt/media`. You can also set them with the `FILE_ROOTS` environment variable (separate paths with `;` on Windows or `:` on Linux/macOS). Settings suggests folders from Radarr, Sonarr and NZBGet.

- **Password required:** anyone who can open Files can change or delete anything in the shared folders, so Files stays switched off until a portal password is set.
- **Contained to shared folders:** paths can't escape the shared folders, including through symlinks or Windows junctions.
- **Large uploads:** files of any size upload in 8 MB pieces. If the connection drops, the current piece is retried automatically, so a big upload doesn't start over. Free space is checked before anything is sent. While an upload is running, phones keep the screen awake (where the browser supports it), and closing the tab asks for confirmation first.
- **Permanent deletes:** deleting is permanent. Nothing goes to the Recycle Bin.
- **Whole folders can't be downloaded:** you can download files, but not a folder in one go.
- **USB drives on your computer:** under **This computer** in the Files sidebar, *Connect a USB drive…* opens a drive (or any folder) plugged into the computer you're using, not the server. Browse it in its own tab, open files in Preview (straight from the drive), make folders, rename and delete, and copy files and folders between it and the server: Copy and Paste, or drag them onto a tab or a shared folder (between your computer and the server, dragging copies; hold Shift to move). Copies to the server go up in resumable pieces like any upload; copies to the drive are written as they download. Nothing on the drive goes to the server unless you copy it. The drive is remembered in that browser: next time, click it and allow access again (the browser asks each time for safety); *Disconnect* (✕) forgets it, and you can unplug the drive once copying has finished. This uses the browser's File System Access API: Chrome, Edge, Opera or Brave on Windows, macOS, Linux or ChromeOS, on MediaDesk's `https://` address (or `localhost`). Firefox and Safari can only read: *Open a USB drive (read-only)…* lets you browse a drive and copy from it to the server.
- **Tabs:** the **+** next to the tabs opens another; *Open in new tab* in a folder's or shared folder's menu, a middle-click or Ctrl+click opens one there. Each tab keeps its own back and forward. Drop files on a tab to move them there (hold Ctrl or Alt to copy). Your tabs are there next time.
- **Connecting network shares:** an admin can connect a share on another computer or NAS in **Settings → Files → Network shares** or with the button next to *Shared folders* in Files: a **Windows / NAS share** (SMB: Windows, Synology, QNAP, TrueNAS, Unraid… paste `\\server\share\folder` or fill in the server, share, user name and password), an **NFS export**, an **SFTP** folder over SSH (a Raspberry Pi, any Linux box) or a **WebDAV** folder (Nextcloud, ownCloud). It becomes one of the shared folders, named as you like, read-only if you want, for Files and every app that uses shared folders (Music, Preview, the eBook Reader…), and per-person folder access applies to it like any other. The MediaDesk server connects (mounts) it into a folder of its own next to `config.json`, reconnects it when MediaDesk starts and every couple of minutes if it drops, and shows *Not connected* (with why) rather than an empty folder when it can't. Passwords stay in `config.json` on the server (SMB's in a file only the server can read while it connects) and are never sent to the browser. The server needs the tools to connect (`cifs-utils`, `nfs-common`, `sshfs`, `davfs2`: all in the Docker image) and permission to mount: run it as root (or with sudo rights to mount), or in Docker uncomment `cap_add`, `devices` and `security_opt` in `docker-compose.yml`. On Windows, Windows / NAS shares connect with `net use` and are used by their `\\server\share` address; connect NFS, SFTP and WebDAV in Windows itself and add the drive as a folder.
- **Network shares on Windows:** the startup task runs as the SYSTEM account, which can't see mapped drive letters such as `Z:`. Use the share's full address, such as `\\NAS\Media`, and make sure the share allows the PC's computer account.
- **Docker:** Files only sees folders mounted into the container. Add each one under `volumes:` in `docker-compose.yml` (for example `- /mnt/media:/media`), then share the container path (`/media`).

After installing, run `restart-windows.cmd` (or press **Check again** in Settings → Files). The startup log lines `Preview helpers: …` and `Archive Expander: …` show where each program was found. The 7-Zip location can also be set with the `SEVENZIP_PATH` environment variable.

## The Game Console

Choose The Game Console's root folder in **Settings → The Game Console** (or set `GAMES_DIR`). Inside it, everything has its place, with a folder per console (`NES`, `SNES`, `N64`, `Game Boy`, `Game Boy Advance`, `Nintendo DS`, `Genesis`, `Sega CD`, `Saturn`, `Dreamcast`, `PlayStation`, `PSP`, `TurboGrafx-16`, `Arcade` and so on):

```
Root folder\ROMS\<console>\<game files>                  cartridge games (NES, SNES, N64, Genesis …)
Root folder\ROMS\<console>\<game name>\<disc files>      disc games (PlayStation, Dreamcast, Sega CD …)
Root folder\BIOS\<console>\<BIOS files>
Root folder\Saves\<console>\<game name>\<save files>
Root folder\Box Art\<console>\<game name>.png
```

In the app, **Settings → Games & storage → Make these folders** creates them all. **Move my games into these folders** moves games you already have (with their track files and cover pictures) and BIOS files into place. Their saves, favourites and play history go with them, and anything MediaDesk doesn't recognise stays where it is. A disc game's folder gives the game its name. A folder holding several discs of one game lists each disc. Saves have readable names such as `Super Mario World (USA) - Battery save.sav`, `… - Save slot 1.state` and `… - Auto save.state`. Saves made before the layout move into it the first time each game is played. A root folder without a `ROMS` folder still works the old way: MediaDesk only reads it and keeps saves with its settings.

MediaDesk works out each game's console from its file type, the folder it's in and, for disc images, the disc itself; sub-folders named after the consoles (`NES`, `SNES`, `N64`, `Genesis`, `PlayStation`, `Game Boy`, …) settle anything ambiguous, such as `.bin` files. Zipped games work. Multi-file discs work as `.cue` (with their `.bin` tracks), `.m3u` playlists or, best, a single `.chd` per disc — browsers have to load the whole disc into memory, so compressed images help.

- **BIOS files:** consoles that need one (Sega CD, Saturn, Dreamcast, 3DO, Lynx, ColecoVision, Atari 5200, and the PlayStation for the more accurate emulator) look for it in `BIOS\<console>`; pick it in the app under *Settings → Consoles*.
- **Box art:** a picture with the same name as the game (next to it, or in a `boxart` / `covers` folder) is used first. Otherwise the server fetches covers from the libretro-thumbnails project (its thumbnail server, or the same pictures on GitHub) when it can reach the internet, and draws one when it can't. Names don't have to match libretro's exactly: `Sonic the Hedgehog (USA)` finds `Sonic The Hedgehog (USA)`, `Super Metroid (USA)` finds `Super Metroid (Japan, USA) (En,Ja)`, and `Legend of Zelda (USA)` finds `Legend of Zelda, The (USA)`. Your region and disc number are preferred, and betas, demos and hacks are avoided. Box art is shown on its own, whole and in its own shape, with nothing behind it. Covers take the shape of each console's usual game box: wider than tall for the Super NES and N64; tall for the NES, Genesis, Master System, Saturn, Atari consoles and most others; square, like a CD case, for the PlayStation, TurboGrafx-16 and Dreamcast; tall UMD cases for the PSP; small near-square boxes for Game Boy and DS. A game's real box art uses its own shape, so PlayStation jewel cases show square and long boxes tall. Where a theme uses tiles of one shape, the art is centred in the tile. To change a game's box art, open the game and choose **Box art…**. You can pick a picture from the shared folders or this device (large pictures are scaled down smoothly), download it again, or use none.
- **Console backgrounds:** a console's section shows a picture of that console behind it. By default this is a public-domain photo from Wikimedia Commons (most are by Evan Amos), which the server downloads the first time and keeps; the photo's credit is shown in the corner. When the server can't reach Commons, a drawing of the console is shown instead. Under *Settings → Consoles* you can choose the photo, the drawing, your own picture or no background for each console.
- **Settings:** changes are saved as you make them. **Save & exit** (or B / Esc) closes Settings.
- **Emulators:** games run in your browser with [EmulatorJS](https://emulatorjs.org) (GPL-3.0) and the libretro cores it packages. MediaDesk doesn't include them: the first time a console is played, the server downloads its emulator from the npm registry (`NPM_REGISTRY` changes where) into its config folder, so it needs internet access once per console. *Settings → Consoles → Download emulator now* fetches one ahead of time.
- **Controllers:** any controller the browser sees as a standard gamepad works (Xbox, PlayStation, Switch Pro, 8BitDo…). Press a button on it once so the browser notices it. In a game, **Home** or **Select + Start** (or **Esc** on the keyboard) opens the game menu: save and load states, restart, change disc, full screen, and quit.
- **On-screen controls:** touch screens get a pad laid out like each console's own controller (six buttons for the Genesis, a stick and C buttons for the N64, and so on). Every finger is tracked separately, so you can hold one button while tapping another (hold B to run and tap A to jump), rest a thumb between two buttons to press both, or slide from one button onto another. To change the layout, use **On-screen controls** in the game menu, or **Customize on-screen controls** under Settings → Consoles. Drag a control to move it; tap it to change its label, shape, size, rotation, colour, colour when pressed, label colour and what it presses. Turn a control with its ↻ handle, or with the rotation slider and its ±15° buttons. To move or turn several controls together, select them with **Select several** (or Shift-click), or drag a box around them. Then drag any one of them to move the group, or turn the group with the ↻ handle or the group panel, which keeps them at the same angle to each other. A turned D-pad or stick turns its directions with it. A button can press several inputs at once (a "B + A" button), map to a hotkey such as fast-forward, or repeat while held (turbo). You can also add D-pads, analogue sticks and buttons, hide or delete them, and change the size and opacity of the whole pad. The N64's C buttons can be four buttons or an analogue stick. Portrait and landscape keep separate layouts. Layouts are saved in the browser, so each device keeps its own.
- **Dreamcast:** played with [flycast-wasm](https://github.com/nasomers/flycast-wasm), Nick Somers' WebAssembly build of Flycast (GPL-2.0). The server downloads release v1.0 from GitHub the first time a Dreamcast game is played and checks it against known hashes. It needs your own Dreamcast BIOS: put `dc_boot.bin` and `dc_flash.bin` in `BIOS\Dreamcast`. Games can be `.chd`, `.gdi` (with its track files) or `.cdi`. Zipped games and Windows CE games (Sega Rally 2 and a few others) don't work with this build. You also need a browser with WebGL 2 and a reasonably fast computer. The memory card (VMU A1) is kept on the server like other battery saves.
- **Adding games:** drag game files from your computer onto the Game Console (or use *Settings → Library → Add games from this device*). Each is uploaded to the server and put in its console's folder: `ROMS/<console>/` with the folder layout (disc games in a folder of their own, BIOS files in `BIOS/<console>/`), otherwise the console's folder at the top of the games folder (an existing one under any of its names, like `Super Nintendo` for SNES). The console comes from the file type, the games inside a zip, a Genesis `.bin`'s header or a disc image's first sectors; when it can't be told (a `.chd` or `.7z`, say), you're asked. Add a `.cue`, `.gdi` or `.m3u` together with its track files and they stay together. A game that's already there is left alone. With accounts, drop on *Shared games* or *My games*. The games folder has to be writable.
- **Own tab:** PSP games open in their own tab, because their emulator needs a page to itself.
- **Docker:** mount your games folder into the container (for example `- /mnt/games:/games`) and set `GAMES_DIR=/games`. It must be writable for saves and box art to go in it; mounted read-only (`:ro`), MediaDesk keeps them with its settings instead.

## The Trip Planner

Trips are kept in `trips/` in the data folder (one file per trip, with its files in `trips/files/`).
To find places, draw routes and show the weather, the MediaDesk server asks these free, open services,
so the server needs internet access for them (the browser only talks to MediaDesk):

| Service | Used for |
|---|---|
| [Photon](https://photon.komoot.io) (OpenStreetMap) | Suggesting destinations as you type, and finding places of a kind nearby and along a road trip's route (quickly; set `PHOTON_URL` to use your own) |
| [Nominatim](https://nominatim.org) (OpenStreetMap) | Searching for places and addresses, and what's at a point on the map (at most one request a second, as its rules ask) |
| [Overpass API](https://overpass-api.de) | A fuller search when Photon finds nothing nearby or along the route. Overpass is often busy, so searches go one at a time, several public servers are tried in turn within a time limit (set `OVERPASS_URLS` to use your own), and Explore falls back to Nominatim when none answers |
| [Wikipedia](https://www.wikipedia.org) | A place's description and picture |
| [FOSSGIS OSRM](https://routing.openstreetmap.de) | Routes on foot, by bike and by car, and driving directions between destinations and to the airport |
| [Open-Meteo](https://open-meteo.com) | Weather forecasts, and last year's weather for days further ahead |
| [Frankfurter](https://www.frankfurter.app) | Exchange rates (from the European Central Bank) |

Map pictures come from OpenStreetMap (and OpenTopoMap for the terrain style) straight to the browser, which tells them only the address of your MediaDesk, as their rules ask. Answers are
cached, and in the demo all of these are answered with made-up data.

A share link (`/trip/…`) and a calendar address (`/trip-feed/….ics`) work without signing in: anyone
who has one can see that trip (a share link shows only what you chose). Make a new one, or stop sharing,
to cut off the old one.

What TREK has that the Trip Planner leaves out: its own accounts and sign-in (OIDC, passkeys; MediaDesk's
password covers it), the AI assistant and MCP server, plugins, TREK Studio photo books, hiking tours with
3D terrain, electric road-trip planning, the Journal and Vacay, group chat, other languages, offline use as
an installed app, reading bookings from e-mails, and the Immich, AirTrail and Dawarich connections.

## Users and sign-in

MediaDesk has user accounts, managed by admins in **Settings → Users**:

- **Roles.** *Admin*: everything, including MediaDesk's settings and the people who use it. *Standard*: every app except the admin-only ones (PiKVM and the Log Viewer, unless an admin ticks them), plus their own settings and personal game library. *Custom*: only the apps an admin ticks. Settings, Search and Preview are always there. The server checks every request, so an app someone doesn't have can't be reached any other way, and services they can't use (and their dashboard widgets) look unset to them. Apps that only open files (Music, eBook Reader, Preview) can read shared folders but not change them.
- **Profile pictures.** Add a picture in *Settings → My account* (an admin can for anyone, in their account). It's cropped square and made small in the browser, and shown on the sign-in screen (for the last person who signed in on that device, and as a user name is typed), in the menu, in Settings → Users and next to people in apps such as the Trip Planner's travellers.
- **Invites.** *Add a person* sends an **invite link** by default, so you don't have to choose a password for anyone: it's emailed to them (if you give an email address and MediaDesk can send email) and shown to copy, and they choose their own password with it. Invites work for 7 days, once; *New invite link* in their account makes another. You can still *Set a password now* instead.
- **Forgotten passwords.** *Forgot your password?* on the sign-in screen emails a link to choose a new one (to the email address on the account; it works for an hour, once, and the answer is the same whether or not an account exists). An admin can also make a reset link for someone in their account, to email or copy. Choosing a new password signs that person out everywhere. Two-step sign-in still asks for the code afterwards.
- **Email server.** Invites and resets are sent through the SMTP server in *Settings → Users → Email* (the same one Send to Kindle uses). Links point at `PUBLIC_URL` if it's set (e.g. `https://media.example.com`), otherwise at the address an admin last used to open MediaDesk.
- **Passkeys.** In *Settings → My account → Passkeys*, add a passkey on each phone or computer (Face ID / Touch ID on Apple devices, a fingerprint or screen lock on Android, Windows Hello, a security key, or a password manager such as iCloud Keychain, Google Password Manager or 1Password). Then *Sign in with a passkey* on the sign-in screen (and the screensaver's lock) signs in without a password or authenticator code: the device itself checks your face, finger or PIN, and the passkey only works on MediaDesk's own address, so it can't be phished. Passkeys are optional, can be renamed or removed, and an admin can remove someone's (a lost phone); the password still works. Browsers only allow passkeys on a secure page, so use MediaDesk's `https://` address (through a reverse proxy, Tailscale and so on) or `localhost`; a passkey belongs to the address it was made on.
- **Shared folders.** Each person sees all of Files' shared folders, or only the ones picked for them.
- **Two-step sign-in.** In *Settings → My account*, anyone can turn on codes from Google Authenticator (or Microsoft Authenticator, Authy, 1Password…): scan the QR code, type a code, and keep the 10 recovery codes. Then signing in asks for the code after the password. An admin can turn it off for someone who has lost their phone.
- **Sessions.** Changing your password, *Sign out everywhere else*, an admin's *Sign them out everywhere*, or turning an account off ends that person's other sessions. Sign-in attempts are rate-limited per address and per account. The screensaver's lock asks the same person for their password (and code), or lets someone else sign in.
- **eBooks: one library, and ♥ Mine.** Every book anyone adds (uploading, dropping onto the library, a Kindle Fire backup) goes into the shared books folder, so everyone can read it. **♥ Mine** is each person's own list of the books they like and want close at hand: books you add go on it (untick *Add them to my ♥ Mine list* to leave them off), and *Add to Mine* / *Remove from Mine* in a book's menu, or the ♥ button while reading, changes it. Taking a book off your list doesn't remove it for anyone else. Books in personal `Books` folders from an earlier version are moved into the shared library (and onto their owner's Mine list) the first time that person opens the eBook Reader.
- **Personal libraries.** Everyone has their own Game Console library and **My files** in Files: a folder of their own (Games and Files) under `users/<user name>` next to MediaDesk's settings, or a folder set in Settings → Users. Reading places, bookmarks, game saves, favourites, play history, app preferences and the Send to Kindle address are each person's own; in the shared Game Console library others' saves go in `Saves/<user name>`. What a browser keeps (desktop layout, appearance, window places) is kept apart for each person who signs in on it.
- **Family Organizer.** Each account can be a parent or a kid in the family, linked to their family profile: kids get their own chores, stars and lists and can't change parent things, as with the organizer's own accounts (which still work on their own at `/family`).
- **Trip Planner.** A new trip belongs to whoever made it, with them as the first traveller. Travellers can be linked to MediaDesk accounts; a trip is seen by its travellers and admins, or by everyone if its settings say so (trips from before accounts are). Each person's calendar feed has their own trips, and Notes and Costs start with "you".

**Before accounts.** Without accounts MediaDesk is open to anyone who can reach it (as before, with a warning when it starts). A portal password from before becomes the password of the **admin** account, and its owner keeps their reading places, saves and desktop. With no password, *Settings → Users → Make my admin account* turns sign-in on.

**Forgotten password.** On the server: `node server.js --reset-password <user name> <new password>` (with Docker: `docker compose exec mediadesk node server.js --reset-password admin <new password>`). This also turns off that account's two-step sign-in. With email set up, *Forgot your password?* on the sign-in screen is easier.

## Custom wallpapers

In Settings → Appearance, choose **Add picture…** to upload one from your device or pick one from the shared folders. You can also right-click a picture in Files and choose **Set as desktop wallpaper**. Pictures are kept in a `wallpapers` folder next to `config.json` (up to 24 pictures, 40 MB each), so every device can use them.

## Security notes

- An admin account has full access to every connected service and MediaDesk's settings: give others the *standard* or *custom* role, and turn on two-step sign-in for admins.
- For access from outside your network, put MediaDesk behind a reverse proxy with HTTPS (Caddy, Traefik, nginx, or SWAG). If the proxy sends `X-Forwarded-Proto: https`, the session cookie is marked `Secure`.
- To sign out, click the MediaDesk logo at the top left and choose **Sign out**. Sign-in attempts are rate-limited, and sessions last 30 days. Accounts are kept in `users.json` next to the config (passwords as scrypt hashes, invite and reset links as SHA-256 hashes, passkeys as public keys only), written with `0600` permissions; profile pictures are in `avatars` next to it. Passkeys are checked by the server itself (challenge, origin, site, user verification, signature and counter), with no outside service.
- The config file is written with `0600` permissions.

## Phones and tablets

Everything works on touch screens too:

- **Same features:** phones and tablets get every feature desktop has, including the widgets (which appear under the desktop icons on phones) and every value in the download queues (shown as labelled cards).
- **Long-press = right-click:** press and hold anywhere you'd right-click with a mouse (files, dock icons, the wallpaper) to open the same menu. Holding an icon-only button shows its name.
- **Selecting in Files:** use the checkboxes, or **Select all** in the header. Once something is selected, tapping other items adds them to the selection; with nothing selected, a tap opens the item. To move files, use Cut and Paste, since dragging isn't available on touch screens.
- **Arranging icons:** hold a desktop icon for a moment, then drag it. Drop it on another icon to make a group, or on the dock to add it. Swiping without holding still scrolls the page.
- **Windows:** on phones every app fills the screen. Switch between apps with the dock.

## Troubleshooting

**Behind Cloudflare or another proxy/CDN:** MediaDesk loads its scripts and styles from addresses that include the build (`/v/<build>/…`), and the page itself is never cached, so updates reach every device even when a proxy caches `.js` and `.css` files. After updating from a version older than this, clear MediaDesk's site data once on each phone (Chrome: ⋮ → Settings → Site settings → All sites → your MediaDesk address → Delete data), or wait a few hours for the old copies to expire. In Cloudflare you can also set **Caching → Configuration → Browser Cache TTL** to *Respect Existing Headers*.

To see what a touch screen is doing, open MediaDesk with `?touchdebug` at the end of the address. A panel then logs each swipe, and **Copy log** copies it.

- **"Could not reach radarr: ECONNREFUSED"**: the URL is wrong *from the MediaDesk server's point of view*. Inside Docker, `localhost` means the MediaDesk container itself, so use the host's LAN IP or the container name instead.
- **A Web UI window is blank**: the service may block being embedded in a frame, or your browser can't reach the public URL. Use "Open in new tab".
- **Plex sign-in finds the server but it won't connect**: pick an address the *MediaDesk server* can reach (usually the `local` one), or type one such as `http://192.168.1.20:32400`. If Plex requires secure connections, choose the `https://…plex.direct` address.
- **Plex video stutters**: lower the quality in the player (⚙) or in *Settings → Plex*.
- **PiKVM shows a picture that updates slowly**: something between your browser and MediaDesk (some reverse proxies) doesn't pass on the live video stream, so the app switched to pictures. You can choose pictures yourself in *Settings → PiKVM* for slow connections.
- **PiKVM keyboard or mouse does nothing**: your reverse proxy must pass WebSockets through to MediaDesk (Cloudflare Tunnel and most proxies do by default; nginx needs `proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade";`).
- **A game says it couldn't load the emulator**: the MediaDesk server couldn't download it from `registry.npmjs.org`. Check the server's internet access (or set `NPM_REGISTRY` to a mirror), then try again.
- **A game is under the wrong console**: move it into a folder named after the right console, then *Settings → Games & storage → Look for new games* in The Game Console.
- **Deleting in Plex fails**: turn on *Allow media deletion* in Plex → *Settings → Library*.
- **Jellyfin shows the wrong user's watch state**: set `JELLYFIN_USER_ID` (or the field in Settings) to your own user ID.
